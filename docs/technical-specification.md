# 1. Общая информация

## 1.1. Назначение проекта

OKU_24 — современная онлайн-платформа для продажи физических печатных книг и аудиокниг.

Платформа должна объединять удобный каталог, интерактивную презентацию книг, прослушивание аудиокниг, онлайн-покупки, личный кабинет пользователя и административную панель.

## 1.2. Основные цели

- Создать современный онлайн-магазин книг.
- Обеспечить удобный поиск и покупку книг.
- Реализовать полноценный аудиоплеер.
- Создать интерактивную 3D-презентацию книг.
- Предоставить администраторам инструменты управления магазином.
- Обеспечить безопасность пользовательских данных.
- Создать масштабируемую архитектуру проекта.

## 1.3. Типы товаров

В проекте предусмотрено два типа товаров:

1. **Физические книги** — печатные экземпляры с возможностью доставки или самовывоза.
2. **Аудиокниги** — аудиоконтент, доступный для прослушивания через встроенный плеер.

Электронные книги в форматах PDF, EPUB и других форматах для чтения не входят в концепцию проекта.

# 4. Архитектура проекта

## 4.1. Тип архитектуры

Проект разрабатывается с нуля в формате Monorepo.

Frontend и Backend располагаются в одном GitHub-репозитории, но работают как отдельные приложения.

Архитектурный подход Backend — Modular Monolith.

## 4.2. Структура репозитория

```text
oku_24/
│
├── apps/
│   ├── web/                  # Next.js Frontend
│   └── api/                  # NestJS Backend
│
├── packages/
│   ├── types/                # Общие TypeScript-типы
│   ├── validators/           # Общие схемы валидации
│   └── config/               # Общие настройки
│
├── docker/                   # Docker-конфигурации
│
├── docs/                     # Документация проекта
│   └── technical-specification.md
│
├── package.json
├── pnpm-workspace.yaml
├── .gitignore
└── README.md
```

Для управления Monorepo предлагается использовать pnpm Workspaces.

## 4.3. Взаимодействие компонентов

1. Пользователь взаимодействует с Frontend на Next.js.
2. Frontend отправляет HTTP-запросы в Backend.
3. Backend на NestJS обрабатывает запросы и бизнес-логику.
4. Prisma выполняет операции с базой данных.
5. Neon PostgreSQL хранит основные данные проекта.
6. S3 Storage хранит аудиофайлы и изображения.
7. CDN обеспечивает быструю доставку медиафайлов.

# 8. Интерактивная 3D-система

3D-система является одной из главных особенностей OKU_24.

## 8.1. Переход из главного 3D-пространства

Переход между 3D-пространствами должен происходить без полной перезагрузки страницы.

Сценарий:

1. Пользователь выбирает 3D-портал.
2. Портал плавно раскрывается.
3. Камера приближается к порталу.
4. Окружение постепенно меняется.
5. Появляется внутренний мир выбранного направления.

## 8.2. Внутренний мир направлений

Утверждённая концепция: Editorial Store.

Внутреннее пространство должно напоминать премиальный интерактивный книжный журнал.

Элементы:

- Большие визуальные обложки.
- Редакционные подборки книг.
- Новинки.
- Популярные книги.
- Категории и жанры.
- Полноценный каталог.

## 8.3. Отображение книг

Утверждённый вариант: объёмные 3D-модели книг с настоящими обложками.

Пользователь должен иметь возможность:

- Рассматривать книгу в объёме.
- Вращать её.
- Приближать и отдалять.
- Взаимодействовать с моделью.
- Переходить на страницу книги.

## 8.4. Страница отдельной книги

Утверждённый вариант: большая интерактивная 3D-книга слева и информация справа.

Структура:

- Слева — 3D-модель книги.
- Справа — название, автор, описание, цена и информация о товаре.
- Ниже — характеристики, отзывы и похожие книги.

## 8.5. Интерактивность 3D-книги

Утверждённый вариант: расширенная интерактивность.

Функции:

1. Вращение книги на 360°.
2. Просмотр передней и задней обложки.
3. Открытие книги.
4. Перелистывание демонстрационных страниц.
5. Приближение и отдаление.
6. Возврат к исходному положению.

Важно: 3D-презентация не является электронной книгой и не предоставляет возможность читать полное цифровое содержимое.

3D-сцены должны быть оптимизированы для мобильных устройств и устройств с ограниченной производительностью.

# 9. Аудиоплеер

## 9.1. Основные функции

- Воспроизведение и пауза.
- Перемотка.
- Изменение скорости воспроизведения.
- Регулировка громкости.
- Переход между главами.
- Отображение текущего времени.
- Отображение общей длительности.
- Сохранение прогресса прослушивания.
- Продолжение с последнего места.

## 9.2. Доступ к аудиокнигам

- Бесплатные фрагменты доступны гостям.
- Полная версия доступна пользователям, получившим право на неё.
- Проверка доступа осуществляется на Backend.
- Платные аудиофайлы не должны иметь открытые публичные ссылки.
- Пользователь не должен получать доступ к неоплаченному контенту через прямой запрос к API.

## 9.3. Хранение аудиофайлов

Аудиофайлы хранятся в S3-совместимом хранилище.

В PostgreSQL сохраняются метаданные и информация о расположении файлов, а не сами аудиофайлы.

# 10. Корзина и оформление заказов

## 10.1. Корзина

Необходимо реализовать:

- Добавление товара.
- Удаление товара.
- Изменение количества.
- Расчёт общей стоимости.
- Проверку доступности товара.
- Сохранение корзины пользователя.

## 10.2. Оформление заказа

Пользователь должен указать:

- Имя и фамилию.
- Номер телефона.
- Адрес доставки, если выбрана доставка.
- Способ получения.
- Способ оплаты.

## 10.3. Статусы заказа

Предусматриваются следующие статусы:

1. Pending — ожидает подтверждения.
2. Paid — оплачен.
3. Processing — обрабатывается.
4. Shipped — отправлен.
5. Completed — завершён.
6. Cancelled — отменён.
7. Refunded — возвращён.

Для аудиокниг после подтверждения покупки должен предоставляться доступ к приобретённому контенту.

# 23. Общие правила разработки

1. Разрабатывать проект с нуля.
2. Не использовать случайные готовые шаблоны вместо согласованного дизайна.
3. Не менять утверждённую архитектуру без согласования.
4. Не создавать неработающие кнопки и декоративные функции вместо реальной логики.
5. Не хранить аудиофайлы непосредственно в PostgreSQL.
6. Не помещать секретные ключи во Frontend.
7. Не дублировать бизнес-логику между Frontend и Backend.
8. Соблюдать строгую типизацию TypeScript.
9. Писать поддерживаемый и структурированный код.
10. Проверять функциональность каждого этапа.
11. Не удалять существующие файлы и рабочую функциональность без предварительного согласования.
12. Перед началом реализации проводить анализ и согласовывать план.
13. После каждого этапа проверять результат и исправлять ошибки.
14. Вести документацию по архитектуре, API и базе данных.

# 24. Итог

OKU_24 — современный онлайн-магазин физических печатных книг и аудиокниг с интерактивной 3D-презентацией, удобным аудиоплеером, системой покупок, личным кабинетом и административной панелью.

Проект должен быть разработан с использованием Next.js, React, TypeScript, Tailwind CSS, NestJS, Prisma ORM и Neon PostgreSQL.

Frontend и Backend должны находиться в одном Monorepo-репозитории.

Главный приоритет — качественный дизайн, реальная работоспособность функций, безопасность, производительность и возможность дальнейшего масштабирования проекта.
